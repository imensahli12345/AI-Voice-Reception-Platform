## 1. Problems when running the project locally

### Problem A: port 5432 already used
- **Error:** `ports are not available: exposing port TCP 127.0.0.1:5432 ... bind: An attempt was made to access a socket in a way forbidden by its access permissions.`
- **Cause:** PostgreSQL 16 is installed on Windows as a service
  (`postgresql-x64-16`) and listens on `0.0.0.0:5432`. Docker cannot open the same port.
- **Decision:** keep the Windows PostgreSQL (needed by another project) and move
  the tenant-portal Docker database to **5433**.
- **Changes made:**

| File | Before | After |
|---|---|---|
| `docker-compose.yml` (db `ports`) | `"127.0.0.1:5432:5432"` | `"127.0.0.1:5433:5432"` |
| `.env.local` line 18 | `...@localhost:5432/tenant_portal` | `...@127.0.0.1:5433/tenant_portal` |

- Inside Docker, the `portal` container still uses `db:5432` (not affected).
- The test container `my-postgres` (plain `postgres` image, port 5433) does not
  work with the project (no pgvector, wrong user/database). Remove it:
  `docker rm -f my-postgres`.

### Problem B: `SyntaxError` in `base.py`
- **Error:** `SyntaxError: ':' expected after dictionary key` at `base.py` line 174.
- **Cause:** a stray `s` typed after the line
  `"AUTH_TOKEN_CLASSES": ("accounts.jwt.PortalAccessToken",),`
- **Fix:** removed the `s`. File compiles again.

### Still to check
- `.env.local` has `EMAIL_HOST=localhost`. DEV_LOG Step 4 says to use
  `127.0.0.1` on Windows. If emails do not reach Mailpit, change it and restart
  `runserver` (email errors are hidden on purpose).

## 3. The 27 tables

**Our own code (6):** `accounts_tenant`, `accounts_user`,
`accounts_user_groups`, `accounts_user_user_permissions`,
`accounts_mfachallenge`, `audit_authevent`.

**Libraries (21):**

| Library | Why | Tables |
|---|---|---|
| Django core (7) | Groups, permissions, migrations, sessions, cache | `auth_group`, `auth_group_permissions`, `auth_permission`, `django_content_type`, `django_migrations`, `django_session`, `django_cache` |
| django-allauth (5) | Email verification, Google login | `account_emailaddress`, `account_emailconfirmation`, `socialaccount_socialaccount`, `socialaccount_socialapp`, `socialaccount_socialtoken` |
| django-otp (3) | MFA (TOTP and backup codes) | `otp_totp_totpdevice`, `otp_static_staticdevice`, `otp_static_statictoken` |
| django-axes (4) | Brute-force protection | `axes_accessattempt`, `axes_accessattemptexpiration`, `axes_accessfailurelog`, `axes_accesslog` |
| simplejwt blacklist (2) | Real logout, refresh rotation | `token_blacklist_outstandingtoken`, `token_blacklist_blacklistedtoken` |

`django_cache` is used for DRF rate limiting (`base.py`: `DatabaseCache`).
`socialaccount_socialapp` stays empty because Google is configured in settings.

**For the jury:**
> "Of the 27 tables, 6 belong to our domain model: tenants, users, MFA
> challenges and the audit log. The other 21 come from proven, widely used
> security libraries: email verification, MFA, brute-force protection and token
> revocation. We chose not to write this security-critical code ourselves. Each
> library manages its own tables through Django migrations, so the whole schema
> is versioned and can be rebuilt with one command."

```powershell
cd "D:\AI Voice Reception Platform\tenant-portal"
$B = "http://127.0.0.1:8000"
$S = New-Object Microsoft.PowerShell.Commands.WebRequestSession   # keeps cookies, like a browser
function Call {
  param($Method, $Path, $Body, $Token, [switch]$Xhr)
  $h = @{}
  if ($Token) { $h["Authorization"] = "Bearer $Token" }
  if ($Xhr)   { $h["X-Requested-With"] = "XMLHttpRequest" }
  $p = @{ Uri = "$B$Path"; Method = $Method; Headers = $h; WebSession = $S; UseBasicParsing = $true; ContentType = "application/json" }
  if ($Body) { $p.Body = ($Body | ConvertTo-Json) }
  try { $r = Invoke-WebRequest @p; $code = [int]$r.StatusCode; $txt = $r.Content }
  catch { if (-not $_.Exception.Response) { throw }; $code = [int]$_.Exception.Response.StatusCode; $txt = $_.ErrorDetails.Message }
  $data = $null; if ($txt) { try { $data = $txt | ConvertFrom-Json } catch { $data = $txt } }
  [pscustomobject]@{ Status = $code; Data = $data }
}
function Jwt($t) { $p = $t.Split('.')[1].Replace('-','+').Replace('_','/'); while ($p.Length % 4) { $p += '=' }; [Text.Encoding]::UTF8.GetString([Convert]::FromBase64String($p)) | ConvertFrom-Json }
function Q($sql) { docker compose exec -T db psql -U portal -d tenant_portal -c $sql }
$E = "demo@clinic.test"; $P = "Blue-Harbor-Lamp-42"
```

### Phase 1: Service alive, public key published
```powershell
Call GET "/health/"                  # 200 {status: ok, database: ok}
Call GET "/health/live/"             # 200 {status: ok}
(Call GET "/.well-known/jwks.json").Data.keys   # kty=RSA, alg=RS256, kid=...
```
Browser: http://127.0.0.1:8000/api/docs/

**Proves:**

- **JWKS:** only the **public** key is published. Other microservices verify our

- **Swagger:** the API is documented automatically.

### Phase 2: Registration
```powershell
# 2a weak password -> 400 (too short / too common)
Call POST "/api/auth/register/" @{company_name="Demo Clinic"; email=$E; password="password123"; first_name="Sara"; last_name="Ben"}
# 2b valid -> 201 "If the details are valid, a verification email has been sent."
Call POST "/api/auth/register/" @{company_name="Demo Clinic"; email=$E; password=$P; first_name="Sara"; last_name="Ben"}
Q "select email, role, is_email_verified, tenant_id from accounts_user where email='demo@clinic.test'"

```
**Proves:**
- **Atomic sign-up:** the tenant and its admin are created together.
- **Password policy:** weak passwords are refused.
- **No account enumeration:** same response and timing whether the email exists or not.

### Phase 3: Email verification and first login
```powershell
Call POST "/api/auth/login/" @{email=$E; password=$P}          # 401 generic message (not verified)
# Mailpit link: http://localhost:3000/verify-email?uid=XXX&token=YYY
$uid = "XXX"; $tok = "YYY"
Call POST "/api/auth/verify-email/" @{uid=$uid; token=$tok}   # 200 "Email verified."
Call POST "/api/auth/verify-email/" @{uid=$uid; token=$tok}   # 400 single use
$r = Call POST "/api/auth/login/" @{email=$E; password=$P}; $r
$T = $r.Data.access_token
Jwt $T                                                        # sub, tenant_id, role, email_verified, iss, aud, exp
$S.Cookies.GetCookies("$B/api/auth/") | Select Name, HttpOnly, Path, Expires
```
**Proves:**
- **Verified email required:** no login until the email is verified.
- **Single-use link:** the verification link works only once.
- **Signed tokens:** RS256 JWT that carries `tenant_id`.
- **Refresh token protection:** stored in an HttpOnly cookie, so JavaScript (and XSS) can't read it.

### Phase 4: Permissions, refresh rotation, logout
```powershell
Call GET "/api/auth/me/"        -Token $T     # 200
Call GET "/api/tenant/me/"      -Token $T     # 200 Demo Clinic
Call GET "/api/admin/tenants/"  -Token $T     # 403 role
Call GET "/api/auth/me/"                      # 401 no token

Call POST "/api/auth/refresh/"                          # 403 missing X-Requested-With
$old = $S.Cookies.GetCookies("$B/api/auth/")["refresh_token"].Value
$r = Call POST "/api/auth/refresh/" -Xhr; $r            # 200 new tokens
$T = $r.Data.access_token
$keep = $S; $S = New-Object Microsoft.PowerShell.Commands.WebRequestSession
$S.Cookies.Add((New-Object System.Net.Cookie("refresh_token", $old, "/api/auth/", "127.0.0.1")))
Call POST "/api/auth/refresh/" -Xhr                     # 401 old token refused
$S = $keep
Q "select count(*) from token_blacklist_blacklistedtoken"

Call POST "/api/auth/logout/" -Xhr     # 204
Call POST "/api/auth/refresh/" -Xhr    # 401
```
**Proves:**
- **Role checks:** a tenant admin can't reach admin endpoints.
- **Tenant from the token:** the tenant comes from the token, never from the URL.
- **Rotation:** every refresh blacklists the old token, so a stolen old token is useless.
- **Real logout:** the refresh token is blacklisted in the database.
- **Limit to state openly:** the 15-minute access token keeps working until it expires. That's normal for JWTs.

### Phase 5: Brute force, lockout, password reset
```powershell
Call POST "/api/auth/login/" @{email=$E; password=$P}       # 200
1..5 | % { (Call POST "/api/auth/login/" @{email=$E; password="wrong-pass-$_"}).Status }   # 401 x5
Call POST "/api/auth/login/" @{email=$E; password=$P}       # 401 even with right password
Q "select failed_login_attempts, locked_until from accounts_user where email='demo@clinic.test'"

Call POST "/api/auth/password-reset/" @{email=$E}           # 200
# Mailpit "Reset your password" -> copy uid and token
$uid = "XXX"; $tok = "YYY"; $P = "Green-River-Stone-77"
Call POST "/api/auth/password-reset/confirm/" @{uid=$uid; token=$tok; new_password=$P}   # 200
Call POST "/api/auth/refresh/" -Xhr                         # 401 all sessions ended
Call POST "/api/auth/login/" @{email=$E; password=$P}       # 200 lock cleared
Call POST "/api/auth/password-reset/confirm/" @{uid=$uid; token=$tok; new_password="Another-Pass-9988"}  # 400
```
**Proves:**
- **Two lockout layers:**
  - Ours: 5 failures lock the account for 15 minutes.
  - django-axes: 10 failures per IP and email block for 1 hour.
- **No hint to the attacker:** even the right password is refused while locked, with the same message.
- **Reset ends every session:** it signs the user out everywhere and unlocks the account.
- **Short-lived links:** reset links work once and expire after 1 hour.

### Phase 6: Platform admin and MFA
```powershell
# third terminal, conda env, in src:
python manage.py createsuperuser      # e.g. admin@platform.test
```
```powershell
Q "select email, role, tenant_id, is_email_verified from accounts_user where role='platform_admin'"
$AE = "admin@platform.test"; $AP = "<password>"
$A = (Call POST "/api/auth/login/" @{email=$AE; password=$AP}).Data.access_token
Call GET "/api/admin/tenants/" -Token $A      # 403 MFA enrollment required

$m = Call POST "/api/auth/mfa/totp/setup/" -Token $A
[IO.File]::WriteAllBytes("$env:TEMP\mfa_qr.png", [Convert]::FromBase64String($m.Data.qr_code_png_base64))
Start-Process "$env:TEMP\mfa_qr.png"          # scan with an authenticator app
Q "select name, confirmed, key from otp_totp_totpdevice"   # key is encrypted
Call POST "/api/auth/mfa/totp/confirm/" @{code="<6 digits>"} -Token $A   # 200 + 10 backup codes (save them)
Q "select count(*), min(token) from otp_static_statictoken"             # 10, hashed
Call GET "/api/admin/tenants/" -Token $A      # 200

Call POST "/api/auth/logout/" -Xhr
$r = Call POST "/api/auth/login/" @{email=$AE; password=$AP}; $r     # mfa_required + mfa_token, no access token
Call POST "/api/auth/mfa/verify/" @{mfa_token=$r.Data.mfa_token; code="000000"}      # 401 mfa_code_invalid
$A = (Call POST "/api/auth/mfa/verify/" @{mfa_token=$r.Data.mfa_token; code="<app code>"}).Data.access_token   # 200
```
**Proves:**
- **MFA required:** admins can't act until MFA is set up.
- **Secrets protected:** the TOTP secret is encrypted and backup codes are hashed.
- **Two steps:** the password alone gives no token. The `mfa_token` lasts 5 minutes, allows 5 attempts, and can't be used as an access token.

### Phase 7: Suspend a clinic
```powershell
$T = (Call POST "/api/auth/login/" @{email=$E; password=$P}).Data.access_token
$tid = ((Call GET "/api/admin/tenants/" -Token $A).Data.results | ? slug -eq "demo-clinic").id
Call POST "/api/admin/tenants/$tid/suspend/" -Token $A    # 200 is_active=false
Call GET "/api/auth/me/" -Token $T                        # 401 User is inactive
Call POST "/api/auth/login/" @{email=$E; password=$P}     # 401
```
**Proves:** suspension is immediate (user and tenant re-checked on every request).
There's no unsuspend endpoint. To undo it:
`Q "update accounts_tenant set is_active=true where slug='demo-clinic'"`

### Troubleshooting
- **No email in Mailpit:** set `EMAIL_HOST=127.0.0.1` in `.env.local`, then restart `runserver`.
- **429 Too Many Requests:** rate limits (register 5/h, reset 5/h, resend 3/h).
  Clear them with `Q "delete from django_cache"`.
- **Rehearsing again:** use a new email and company name.
- **401 after a pause:** the access token expired (15 minutes). Log in again.
